## 0. 一页摘要

三个参考项目各自解决了一部分问题，但都不能单独胜任真实使用：

- **AutoCourse-DB** 有干净的自建题库（选项乱序无关的稳定 Key、AI 答题自动入库、纯标准库零依赖），但没有界面、一次只能挂一门课、不支持图片题、配置写死在代码里。
- **ocs-ai-answerer** 有最完整的 AI 能力（多模型管理、题型映射、故障转移、深度思考、图文混排多模态、答案清洗），但代码是 4040 行的单文件，没有题库，前端要 Node 构建 + CDN，离线即废。
- **ocsjs-ai-answer-service** 有像个「产品」的 Web 控制台（导航、统计面板、测试页、API 文档页），但答题逻辑极其单薄（`extract_answer` 甚至会把任意含 A/B/C 的行当答案），没有题库、没有图片、没有模型管理。

**AnswerHub 的做法**：以 AutoCourse-DB 的「稳定 Key 题库」为数据内核，把 ocs-ai-answerer 的「多模型 + 图片题 + 答案清洗」作为离线未命中时的智能兜底，再套上 ocsjs-ai-answer-service 那种「打开网页就能用」的控制台，并把三者互不兼容的接口协议**全部兼容**——同一个 8000 端口同时响应 `/search`、`/api/answer`、`/api/search`，用户原来那份 OCS 配置一个字都不用改。

一句话：**命中题库零 Token，未命中才问 AI，答完自动进库，全过程一个网页看得见。**

## 1. 需求与目标

### 1.1 背景

OCS（Online Course Script）网课助手通过「题库接口」把题目 POST 给本地服务，取回答案。现有三个项目都在做同一件事的不同侧面，但用户实际使用时会遇到以下断点：

1. 想用 AI 答题 → 装 ocs-ai-answerer → 3000 道题重复消耗 Token，且没有本地沉淀。
2. 想用本地题库 → 装 AutoCourse-DB → 一次只能挂一门课，换课要重启、要手改 `ocs.py`。
3. 遇到图片题 → 题库里没有，AI 项目又没配多模态模型 → 直接失败。
4. 想改个参数 → 要么编辑 `.env`，要么编辑 Python 源码顶部的 CONFIG 字典。
5. 想看看今天答了多少题、AI 花了多少钱 → 要么翻 CSV，要么靠控制台滚屏。

### 1.2 用户画像

| 角色 | 关心什么 | 典型诉求 |
| --- | --- | --- |
| 普通使用者 | 能跑、别报错、别花钱 | 双击 bat → 浏览器打开 → 粘贴 OCS 配置 → 做题 |
| 题库维护者 | 题库质量、去重、纠错 | 导入别人的 JSON、批量检查、标记错误答案、导出分享 |
| 折腾党 / 开发者 | 可控性 | 自定义模型、代理、端口、模糊匹配阈值、看请求链路 |

| NFR-07 | 依赖体积 | 运行时依赖 ≤ 3 个（flask、requests、python-dotenv 均可选） |

### 1.5 明确不做（本期范围外）

- 不做题库云端同步 / 账号体系 / 多人协作。
- 不做浏览器插件，不接管 OCS 的答题点击逻辑（只做接口）。
- 不做 OCR 引擎本地部署（图片题走多模态大模型，不做离线 OCR）。
- 不做移动端适配（响应式能看清即可，不专门优化手机）。
- 不内置任何题库内容分发，不提供任何「保证正确」的答案来源。

## 2. 现有三项目分析

### 2.1 AutoCourse-DB（题库内核的来源）

**结构**：`ocs.py`（225 行，纯标准库）+ `libraries/*.json` + `AutoCourse-DB.exe`（PyInstaller 打包，9.1 MB）+ `OCS题库配置.json`。

**核心机制**（值得完整继承）：

1. **稳定 Key**：`storage_key = f"[{type}] {title} | {sorted(option_texts) joined by ' | '}"`。
   选项文本排序后拼接，因此平台把 A 和 C 的内容对调，Key 不变（`ocs.py:63-88`）。
2. **答案存内容不存字母**：AI 返回 `A#B`，入库时经 `opts_dict` 转成 `苹果#香蕉`；回填时再查当前页面的 `reverse_opts` 把内容映射回当前的字母（`ocs.py:103-110`、`ocs.py:124-131`）。
3. **JSON 即题库**：一门课一个文件，Key 直接是可读的 `[single] 题目 | 选项1 | 选项2`，人类可 diff、可提交 PR。
4. **双重校验防水数据**：AI 返回空、纯空格、纯 `#` 时不入库（`ocs.py:118-139`）。
5. **零依赖**：`http.server` + `urllib`，无需 pip。

**实测数据**：开发期用两个真实课程题库（共 **153 题**：47 单选 / 54 多选 / 52 判断）做了全量回归，全部为 JSON 平面字典。**本仓库不附带这些题库**，只留一份演示用的 `libraries/示例题库.json`。

**局限**：单课程、无 GUI、无图片题、无模糊匹配、配置写死、端口固定 8000、无日志/统计、无去重与质量标记。

**许可证**：MIT（Copyright © 2026 JinHeng）→ 可复用，保留版权声明。

### 2.2 ocs-ai-answerer（AI 能力的来源）

**结构**：单文件 `ocs_ai_answerer_advanced.py`（4040 行）+ Vue3 前端（`frontend/`，需 `build_frontend.bat` 构建）+ 旧版 `config_panel.html`（1105 行，单文件可直接用）+ CSV 日志 + `custom_models.json`。

**核心机制**（值得移植）：

| 能力 | 位置（行号） | 要点 |
| --- | --- | --- |
| 模型管理器 | `352-847` | `models` 字典 + `question_type_models` 五类映射（single/multiple/judgement/completion/**image**），含 `_sanitize_question_type_mappings` 自动剔除图片题里的非多模态模型 |
| 内置预设引导 | `848-1009` | 3 个内置预设 + 版本号迁移，旧 `.env` 首次迁移 |
| 安全模块 | `1012-1215` | 64 位随机密钥、SHA256 存储、失败 5 次锁 5 分钟、`@require_auth` |
| Prompt 构建 | `1229-1394` | 五类题型分别定制，含「只输出字母」与「只输出内容」两套模板 |

| 图片下载 | `1681-1719` | 带 `Referer: mooc1.chaoxing.com` 的 UA，转 Base64 data URI |

| 多协议 API | `1877-2005` | 同时支持 `chat_completions` 与 OpenAI `responses` API |

**局限**：单文件 4040 行难维护；前端 Vue 需要 Node 构建、CDN 引 Element Plus；无题库（每题必调 AI）；`.env` 改参数；CSV 记录难查询；`host=0.0.0.0` 且配置接口暴露，安全面偏大。

**许可证**：MIT（Copyright © 2025 Liu Keda）→ 可复用，保留版权声明。

### 2.3 ocsjs-ai-answer-service（GUI 形态的来源）

**结构**：Flask + Jinja2 模板 + Bootstrap CDN + `SimpleCache`（MD5 Key + TTL）+ `api_docs.md`。

**值得借鉴**：
- 页面组织：**首页（手动测试）→ 统计面板 → API 文档** 三段式，用户一进去就知道「这玩意儿是干嘛的」（`templates/index.html`）。
- `SimpleCache(86400)`：问题+类型+选项 的 MD5 作为缓存键（`utils.py:12-96`）。
- `format_answer_for_ocs()`：极简 `{code:1, question, answer}` 响应（`utils.py:99-114`）。
- 健康检查 `/api/health` 返回 model / cache 状态（`app.py:175-184`）。

**局限**：`extract_answer` 逻辑有缺陷（只要行里出现 A/B/C 就拼成答案）；无题库、无多模型、无图片、无认证体系；模板直接 `f"""..."""` 拼 HTML；无许可证文件（**不得直接复制其代码，仅借鉴交互设计**）。

## 3. 总体架构

### 3.1 设计原则

1. **离线优先（Offline-first）**：能查库绝不打模型；AI 是兜底而不是主路径。
2. **零构建前端**：HTML/CSS/JS 直接由 Flask 托管，不引入 Node、不引 CDN，断网也能打开管理台。
3. **协议即适配器**：核心流水线只有一条，历史协议只是「请求解析 + 响应渲染」的薄适配层。
4. **一切可回滚**：题库是 SQLite 单文件，配置是 JSON 单文件，删掉 `data/` 即恢复出厂。
5. **默认安全**：默认只监听 `127.0.0.1`，管理接口默认只允许本机，密钥回显必脱敏。
6. **可移植的复用**：MIT 代码按模块搬入并标注出处；无许可证项目只借鉴形态、重写实现。

### 3.3 技术选型与理由

| 决策点 | 选择 | 备选 | 理由 |
| --- | --- | --- | --- |
| 语言 | Python 3.9+ | Node / Go | 三个参考项目都是 Python；本机已装 3.14.9 且 Flask 就绪；用户迁移成本最低 |
| Web 框架 | Flask 3.x + flask-cors | 标准库 `http.server` | 需要路由/模板/JSON/静态文件/多线程；`http.server` 写起来太原始（AutoCourse-DB 的痛点） |
| 生产 WSGI | `waitress`（可选，缺失则退回 `app.run(threaded=True)`） | gunicorn / uwsgi | Windows 友好、纯 Python、无编译 |
| 题库存储 | **SQLite（stdlib sqlite3）** | 每课一个 JSON / TinyDB | 需要去重、索引、模糊候选、命中计数、日志统计；JSON 用作**导入导出格式**保留互通 |
| 前端 | 原生 HTML + CSS + JS（ES2020，无框架） | Vue3（answerer）/ Bootstrap（service） | 免 Node 构建；离线无 CDN；单文件可审阅；图表用内联 SVG 手绘 |
| 配置存储 | 单个 `data/config.json` | `.env` | GUI 一键保存；结构可嵌套（模型/映射）；仍读取 `.env` 覆盖（兼容 answerer 用户） |
| 模型调用 | `requests` 直连 HTTP | `openai` SDK（answerer 用） | `requests` 更小更可控，避免 SDK 版本漂移；`responses` 协议也能自己拼 |
| 日志 | SQLite `answer_logs` 表 | CSV | 可过滤/分页/聚合；导出仍给 CSV |
| 打包 | bat（主）+ PyInstaller（可选） | Nuitka / Electron | 用户明确要「双击运行」；PyInstaller 已在本机可用 |

> 依赖策略：**必需** `flask`；**推荐** `requests`（缺失则用 `urllib` 走同样逻辑）；**可选** `waitress`、`python-dotenv`。`requirements.txt` 全部列出但不强绑版本。

**设计说明**

- 为什么 `title` 与 `original_title` 分开：归一化用于匹配，原文用于导出与人工阅读；导出时优先 `original_title`，保证 AutoCourse-DB 格式往返一致。
- 为什么 `answer_json` 存内容而不是字母：这是 AutoCourse-DB 的核心防错设计——选项乱序时字母会错，内容不会。
- `UNIQUE(course_id, canonical_key)` 保证同课程内不会重复入库；导入时冲突走「保留已验证 / 覆盖未验证」策略。
- 日志与题库分表：日志增长快，不能拖慢查库。

### 4.2 题目归一化算法（核心）

```python
def normalize_text(s: str) -> str:
    s = unicodedata.normalize('NFKC', s or '')      # 全角→半角（Ａ→A、（→(）
    s = s.replace('\u3000', ' ')                     # 全角空格
    s = QUOTE_MAP.sub(lambda m: '"', s)              # “”‘’ → "
    s = re.sub(r'\s+', ' ', s).strip()               # 压缩空白
    s = re.sub(r'^(?:第\s*\d+\s*[题道]|\d+\s*[.、)）])\s*', '', s)  # 去题号前缀
    s = s.lower()                                    # ASCII 大小写归一
    return s

def canonical_key(qtype: str, title: str, option_texts: list[str]) -> str:
    t = normalize_text(title)
    opts = sorted({normalize_text(o) for o in option_texts if normalize_text(o)})
    return f"[{qtype}] {t} | {' | '.join(opts)}"     # 与 AutoCourse-DB 完全一致
```

**规则清单（必须单测覆盖）**

| 输入 | 期望 |
| --- | --- |
| `A. 苹果` / `Ａ．苹果` / `A、苹果` / `A 苹果` | 都解析为 `苹果` |
| 选项顺序 `[苹果,香蕉]` vs `[香蕉,苹果]` | 同一 `canonical_key` |
| 题干含全角括号、全角逗号 | NFKC 后与半角版本同 Key |
| 题干末尾 `（ ）` / `(  )` | 保留（是题干的一部分，不删除） |
| 题干前导 `1.` `第3题` `(2)` | 去除 |
| 判断题无选项或选项为 `对/错` | 选项参与 Key 但不影响答案判定 |
| 同一选项内容重复 | 集合去重 |

> 与 AutoCourse-DB 的差异：额外做 NFKC 与小写归一、去题号，因此**同一道题在不同平台抓到的文本差异**也能命中；同时保留 `legacy_key` 让导入的旧题库 100% 可命中。

### 4.3 选项解析

OCS 传来的 `options` 有三种形态，必须全部支持：

1. **字符串（换行分隔，带字母前缀）**：`"A. 苹果\nB. 香蕉"` —— AutoCourse-DB 与 OCS 默认格式。
2. **字符串数组**：`["A. 苹果", "B. 香蕉"]` 或 `["苹果", "香蕉"]` —— answerer 的 `/api/answer`。
3. **纯文本（无字母）**：`"苹果\n香蕉"` —— 部分平台的判断题/填空。

```python
LETTER_RE = re.compile(r'^\s*([A-Za-z]|[①②③④⑤⑥⑦⑧⑨⑩]|[（(]?[1-9][)）.、])\s*[.、:：)）]?\s*(.*)$')

def parse_options(raw) -> list[str]:
    lines = split_lines(raw)                 # 支持 str / list[str]
    out, cur = [], None
    for line in lines:
        m = LETTER_RE.match(line)
        if m and m.group(2):                 # 有前缀 → 新选项
            out.append(m.group(2).strip())
            cur = len(out) - 1
        elif cur is not None:                # 无前缀 → 续行拼到上一个选项
            out[cur] = (out[cur] + ' ' + line.strip()).strip()
        else:
            out.append(line.strip())         # 首个选项就没有前缀
    return [o for o in out if o]
```

**边界**：`A. B. 某选项`（选项内容本身以字母开头）、选项是图片 URL、选项为空（填空题）。解析结果与「原始顺序」严格保持对应，`use_option_labels` 由「任一选项疑似图片 URL 或纯字母」判定。

### 4.4 答案存储与回填

**存储**：`answer_json = ["内容1", "内容2"]`（多选排序无关，比对时用集合）；判断题存 `["对"]` 或 `["错"]`；填空题存原文（可能含 `#` 分隔的多空）。

**回填（题库 → 当前页面）**：

```python
def to_letters(answer_contents, options, qtype):
    if qtype == 'judgement':  # 判断题：内容 → 对/错，由 answer.py 归一
        return normalize_judgement(answer_contents)
    letters = []
    for content in answer_contents:
        idx = find_option_index(content, options)   # 精确 → 去标点 → 包含 → 相似度≥0.8
        letters.append(chr(65 + idx) if idx is not None else content)  # 兜底返回内容
    return '#'.join(sorted(set(letters)) if qtype == 'multiple' else letters)
```

**回填失败兜底**：若一个都匹配不上，直接返回存储的内容（OCS 允许按内容匹配），并记日志 `fuzzy_options=1` 供排查。

### 4.5 兼容导入导出

**导入（AutoCourse-DB JSON）**

```json
{
  "[single] 题目文本 | 选项1 | 选项2": "选项1",
  "[multiple] 题目文本 | 选项1 | 选项2 | 选项3": "选项1#选项3",
  "[judgement] 判断题文本 | 对 | 错": "对"
}
```

解析策略（**双保险**）：
1. 用正则 `^\[(\w+)\]\s*(.*)$` 取类型与剩余部分。
2. 剩余部分按 ` | ` 切分：第一段视为题干，其余视为选项。题干自身含 ` | ` 的极端情况无法无歧义还原 → 此时 **原样保存 `legacy_key`**，查库时优先精确比对 `legacy_key`，保证命中率不降。
3. 答案按 `#` 切分，逐个在选项里定位；定位不到就视为「内容型答案」直接保存。
4. 同时写入新课程（文件名即课程名），`source='import'`, `verified=1`（视为已校验）。

**导出**：默认导出 `canonical_key` 格式（与 AutoCourse-DB 完全可互换）；提供「保持 legacy_key」开关。导出文件名 = 课程名 + `.json`，`ensure_ascii=False, indent=2`。

**实测基线**：导入一个真实题库后，用原文再次查询应 100% 命中（作为 M1 验收用例）。

## 5. 答题主流程

### 5.1 流水线

```
① 解析协议 → 统一请求 {title, options[], qtype, images[], protocol}
② parse_options + normalize → canonical_key, legacy_key
③ 内存缓存命中？ ──是──▶ 返回（hit_source=cache）
④ 精确匹配（当前课程） ─命中─▶ 回填字母 → 返回（exact）
⑤ legacy_key 匹配      ─命中─▶ 回填 → 返回（legacy）
⑥ 模糊匹配（可关，阈值默认 0.92，限同课程同题型）─命中─▶ 返回（fuzzy, 记相似度）
⑦ AI 兜底（可关）
   ├─ 选模型：题型映射 → 过滤多模态（有图时）→ 按顺序尝试
   ├─ 组 Prompt（prompt.py）+ 图片（images.py）
   ├─ 调用（ai.py），失败换下一个模型
   ├─ 清洗（answer.py）→ processed / ocs_answer
   └─ 入库（source=ai, verified=0）——按配置 auto_save 开关
⑧ 写日志 + 写缓存
⑨ 按协议渲染响应
```

**降级约定**：AI 未配置 / 全部失败 → 返回协议允许的「未找到」但不抛 500（AutoCourse-DB 返回 `"未找到答案"`、answerer 返回 `success:false`、service 返回 `code:0`），并保证 OCS 侧不会卡死。

**模糊匹配细节**：
- 仅对「同课程 + 同题型」的候选集计算；候选预筛用「题干 2-gram 重合度 ≥ 0.5」把候选压到 ≤ 200 条。
- 相似度 = `difflib.SequenceMatcher(None, a, b).ratio()`，题干权重 0.7、选项集合 Jaccard 0.3。
- 命中后**不自动改库**（避免错题扩散），仅返回答案并记 `similarity`。

### 5.2 图片题子流程

```
题干/选项文本 ──regex──▶ 图片 URL 列表
   ├─ clean_url：截断到最后一个图片扩展名
   ├─ 过滤图标：/icon/、video.png、audio.png、play.png…
   ├─ 去重（同一 URL 只下一次）
   ├─ 下载：requests（UA + Referer: mooc1.chaoxing.com），超时 15s，上限 5 MB
   ├─ 磁盘缓存：data/cache/images/<sha1(url)>.<ext>，命中直接读
   └─ Base64 data URI → 图文混排消息
```

**图文混排**（移植 `ocs_ai_answerer_advanced.py:1789-1854`）：
1. 若全部图片下载成功且每个 URL 都在 prompt 中出现 → 按出现位置把 `image_url` 块插回文本之间，并加 `[Question Image 1]` / `[Option A]` 标签；
2. 否则回退「先全部图片、再整段文本」；
3. prompt 中明确要求「选项是图片时只回字母」。

**模型约束**：有图片时只用 `is_multimodal=true` 的模型；若题型映射里没有 → 自动在该题型可用模型里挑多模态的 → 仍没有则降级纯文本并记 `image_degraded=1` 警告。

### 5.3 模型选择与故障转移

```python
def pick_models(qtype, has_images):
    mapping = config['type_mapping'][qtype]           # {models:[], enable_reasoning:bool}
    ids = mapping['models'] or config['fallback_models']
    models = [m for m in map(get_model, ids) if m and m['enabled']]
    if has_images:
        mm = [m for m in models if m['is_multimodal']]
        if mm: models = mm
        else:  models = [m for m in models]  # 降级 + 警告
    return models
```

- 顺序即优先级，GUI 用「上移/下移」调整。
- 每个模型失败原因（超时 / 401 / 429 / 空回答 / JSON 解析失败）记日志，UI 在模型卡片上显示「最近一次失败原因」。
- 429 / 5xx 才换模型；401 / 403 直接判定「该模型配置错误」但仍继续尝试下一个。
- 有图片时若首个模型非多模态 → 跳过并提示。

### 5.4 缓存

- 内存 `OrderedDict` LRU，容量 512，TTL 默认 3600 s，Key = `course + canonical_key`。
- 命中缓存写日志 `hit_source=cache`，`latency_ms` 极低，统计里单独展示。
- GUI 提供「清空缓存」按钮（`POST /api/cache/clear`）。
- 进程重启缓存即失效，不影响题库。

### 5.5 三种协议的答案格式

| 协议 | 端点 | 请求 | 响应 | 答案格式 |
| --- | --- | --- | --- | --- |
| AutoCourse-DB 兼容 | `POST /search` | `{title, options:"A. x\nB. y", type:"single"}` | `{"answer":"A#C"}` | **字母**（该协议生态的既有行为） |
| answerer 兼容 | `POST /api/answer` | `{question, options:[...]或字符串, type:0/1/3/4, images:[...]}` | `{success, answer, ocs_answer, ocs_format:[title, ans, {ai,tags,...}], model, usage…}` | **内容**（选项为图片时回字母/URL） |
| service 兼容 | `GET|POST /api/search` | 表单或 JSON `{title, type, options}` | `{code:1, question, answer}` | **内容** |
| 本项目原生 | `POST /api/v1/ask` | 统一结构 | `{ok, answer, letters, source, qtype, model, timing, trace[]}` | 两者都给 |

> `answer_format` 配置项可强制 `letters` / `content` / `auto`（auto = 按协议默认）。

| POST | `/api/questions/bulk-verify` | 批量标记已校验 | 是* |
| GET | `/api/logs` | 分页 + 过滤 `?source&qtype&from&to&q` | 否 |
| GET | `/api/logs/export` | 导出 CSV | 否 |
| POST | `/api/logs/clear` | 清空日志 | 是* |
| GET | `/api/stats?days=7` | 趋势/分布/命中率/成本 | 否 |
| POST | `/api/test/ask` | GUI 测试（支持图片上传 multipart） | 否 |
| GET | `/api/ocs-config?style=` | 生成 OCS 配置 JSON | 否 |
| POST | `/api/cache/clear` | 清空内存缓存 | 是* |

`是*` = 仅在配置了访问令牌时校验；且所有 `/api/*` 管理接口默认额外限制 `remote_addr ∈ {127.0.0.1, ::1}`（可通过 `security.allow_lan_admin` 放开）——因为配置里含 API Key。

### 6.4 错误码

| HTTP | 场景 | 响应体 |
| --- | --- | --- |
| 200 | 成功（含「未找到答案」的业务失败） | 协议对应结构 |
| 400 | 请求体非法 / `title` 为空 | `{"ok":false,"error":"题目不能为空"}` |
| 401 | 令牌缺失或错误 | `{"ok":false,"error":"无效的访问令牌"}` |
| 403 | 管理接口来自非本机 | `{"ok":false,"error":"仅允许本机访问管理接口"}` |
| 429 | 令牌连续错误过多 | `{"ok":false,"error":"尝试过于频繁，请 5 分钟后再试"}` |
| 500 | 未捕获异常 | `{"ok":false,"error":"服务器内部错误","request_id":"..."}` |

**注意**：答题接口在「AI 未配置 / 全部模型失败」时返回 **200 + 业务失败结构**，绝不返回 5xx，因为 OCS 会把 5xx 当网络错误并反复重试刷屏。

### 6.5 OCS 配置生成

GUI「接入方式」页按当前端口动态生成三份，一键复制：

```json
[
  {
    "name": "OCS智题库-本地题库优先",
    "url": "http://127.0.0.1:8000/search",
    "method": "post",
    "type": "GM_xmlhttpRequest",
    "contentType": "json",
    "data": { "title": "${title}", "options": "${options}", "type": "${type}" },
    "handler": "return (res) => [undefined, res.answer]"
  }
]
```

（另两份为 `/api/answer` 的 `fetch` 版本与 `/api/search` 的 `GM_xmlhttpRequest` 版本，与现有项目配置等价。）

## 9. 非功能设计

### 9.1 并发与数据库

- SQLite `WAL` + 单写连接（`threading.Lock`）+ 每线程读连接；写操作（入库/日志）短事务，避免锁表。
- Flask 以 `threaded=True` 启动；若装了 `waitress` 则 `waitress.serve(app, threads=8)`。
- 日志写入改为「队列 + 后台线程批量 flush（每 200 ms 或 50 条）」，避免 IO 拖慢答题；进程退出时 flush。
- 图片下载在主线程内同步进行（单题 ≤ 3 张的常见场景足够）；不引入线程池复杂度。

### 9.2 安全

1. 默认 `127.0.0.1` 绑定。
2. 管理接口本机校验（`security.py: is_local_request`）。
3. 可选令牌：`X-Access-Token` 头或 `?token=`；SHA256 存哈希，弱比较用 `hmac.compare_digest`。
4. 失败限流：IP → 尝试时间戳队列，5 次 / 300 s。
5. 前端无 `innerHTML` 拼接用户数据（统一 `textContent`），防 XSS（题库内容来自网络，必须做）。
6. 上传图片限制：仅 `png/jpg/jpeg/webp/gif`，≤ 5 MB，按 magic number 校验而非扩展名。
7. 不执行任何来自题库/配置的代码（AutoCourse-DB 的配置里含 JS handler，我们只**生成**不执行）。

### 9.3 日志与可观测性

- `data/logs/app.log`：滚动（5 MB × 3），格式 `时间 | 级别 | 模块 | 消息`。
- 控制台同步输出精简版（启动横幅、每题一行结果、错误）。
- 答题日志入 SQLite，GUI 可查；同时支持「导出 CSV」给 Excel 用户。
- 每题分配 `request_id`（时间戳微秒），错误响应里回传，便于与 app.log 对齐。

### 9.4 容错

| 故障 | 行为 |
| --- | --- |
| AI Key 未配置 | 不报错，返回「未找到」，GUI 顶部黄条提示「未配置模型」 |
| AI 超时 | 换下一个模型；全失败则返回未找到 + 日志记 `error` |
| 图片下载失败 | 跳过该图，其余继续；全失败则纯文本 |
| 数据库损坏 | 启动时 `PRAGMA integrity_check`；失败则重命名为 `bank.db.corrupt-<ts>` 并新建空库，提示用户从备份/导出恢复 |
| 端口被占 | 启动时探测；被占则打印明确提示并建议 `--port 8001`，不静默换端口（避免 OCS 配置错位） |
| 配置文件损坏 | 备份为 `config.json.bad`，用默认值启动并提示 |

### 9.5 离线能力

- 除 AI 调用外，所有功能（查库、GUI、导入导出、统计）零网络依赖。
- 无 CDN、无在线字体、无遥测。
- 首次 `pip install` 需联网；若本机已有 Flask 则完全离线可跑。

### 9.6 性能预算

| 环节 | 预算 |
| --- | --- |
| 精确查库（SQLite 索引） | < 3 ms |
| 全流程（命中） | < 20 ms |
| 模糊匹配（200 候选） | < 40 ms |
| 日志写入（异步） | 不阻塞主流程 |
| GUI `/api/questions` 分页 | < 50 ms / 50 行 |
| 首页 HTML+CSS+JS | < 120 KB（未压缩） |

## 10. 启动器与交付

### 10.1 `一键启动.bat` 设计

```bat
@echo off
chcp 65001 >nul
setlocal enabledelayedexpansion
cd /d "%~dp0"
title OCS 智题库 · AnswerHub

echo ╔══════════════════════════════════════════════╗
echo ║      OCS 智题库 · AnswerHub  v1.0.0          ║
echo ╚══════════════════════════════════════════════╝
echo.

REM 1) 找 Python（优先 py -3，其次 python）
set "PY="
where py >nul 2>&1 && set "PY=py -3"
if not defined PY ( where python >nul 2>&1 && set "PY=python" )
if not defined PY (
  echo [错误] 未检测到 Python 3.9+。
  echo        请到 https://www.python.org/downloads/ 安装，安装时勾选 "Add python.exe to PATH"。
  pause & exit /b 1
)

REM 2) 虚拟环境（首次较慢，之后秒开）
if not exist ".venv\Scripts\python.exe" (
  echo [1/3] 首次运行，正在创建虚拟环境...
  %PY% -m venv .venv
  if errorlevel 1 ( echo [警告] 虚拟环境创建失败，将使用系统 Python。 & set "RUNPY=%PY%" )
)
if exist ".venv\Scripts\python.exe" set "RUNPY=.venv\Scripts\python.exe"

REM 3) 依赖自检（只装缺的）
"%RUNPY%" -c "import flask" >nul 2>&1
if errorlevel 1 (
  echo [2/3] 正在安装依赖（首次需要联网）...
  "%RUNPY%" -m pip install -r requirements.txt --disable-pip-version-check -q
  if errorlevel 1 ( echo [错误] 依赖安装失败，请检查网络或换用国内源。 & pause & exit /b 1 )
)

REM 4) 启动（--open-browser 由 Python 在健康检查通过后打开）
echo [3/3] 正在启动服务...
"%RUNPY%" -m app.main --open-browser
if errorlevel 1 ( echo. & echo [错误] 服务异常退出，请查看上方日志。 & pause )
endlocal
```

**关键点**

- `cd /d "%~dp0"`：保证从任何位置双击都能定位项目目录（AutoCourse-DB 的老坑）。
- 依赖检测用 `import flask` 而不是对比 requirements 时间戳，简单可靠。
- `python -m app.main`（模块方式）避免相对导入问题。
- `--open-browser`：Python 侧轮询 `/api/health` 最多 15 s，成功再 `webbrowser.open`，避免打开白页。
- 出错一律 `pause`，用户能看清报错（双击运行的经典问题：窗口一闪而过）。
- 控制台**不关闭**，作为实时日志窗口；Ctrl+C 或关窗即停止服务。

- 调用 `python -m PyInstaller --noconfirm --clean`，spec 文件内 `datas=[('web','web'),('config.example.json','.')]`。
- 产物 `dist/OCS-AnswerHub.exe`，`data/` 与 exe 同级生成（`sys._MEIPASS` 只读，写入一律走 exe 目录）。

## 13. 风险与对策

| # | 风险 | 影响 | 对策 |
| --- | --- | --- | --- |
| R1 | 各平台 `options` 格式千奇百怪，解析失败导致答案错位 | 高 | 解析器单测覆盖 10+ 形态；解析失败时退回「按行切分 + 索引即字母」；日志记录原始 options 供排查 |
| R2 | AI 答案错误被自动入库并扩散 | 高 | 默认 `verified=0`（待校验）+ GUI 校验筛选 + 答案内容存文本而非字母（便于人工判断） |
| R3 | 图片 URL 需要 Referer/Cookie 才能下载 | 中 | 带 `mooc1.chaoxing.com` Referer；失败则跳过图片并在答案标签提示「图片未读取」 |
| R4 | 模糊匹配误命中同课相似题 | 中 | 阈值 0.92 默认；命中不写库；GUI 可关；日志记录相似度便于复盘 |
| R5 | API Key 明文存 `data/config.json` | 中 | 默认本机绑定 + 管理接口本机限制 + 回显脱敏；文档提示「勿把 data 目录发给别人」 |
| R6 | 端口 8000 与 AutoCourse-DB 冲突 | 中 | 启动检测并明确报错；`--port` 参数；GUI 生成配置时自动用当前端口 |
| R7 | Python 3.14 新版本兼容性（第三方库滞后） | 中 | 只用 flask/requests 这两个成熟库；不引 pandas/numpy；本机已验证 Flask 3.1.3 + requests 2.34 可用 |
| R8 | 单进程 + 异步日志线程退出丢日志 | 低 | `atexit` flush + 信号处理；日志失败不影响答题 |
| R9 | 用户把 `data/` 放到 OneDrive 同步导致 SQLite 锁 | 低 | 文档提示；`integrity_check` + 损坏自愈 |
| R10 | 合规风险（网课平台服务条款） | 中 | 明确「仅供编程学习与接口测试」，不提供任何题库内容、不绕过任何付费/考试环节 |

### 14.2 判断题归一表

`对/正确/是/√/true/T/1` → `对`；`错/错误/否/×/false/F/0` → `错`。选项只有「对/错」「正确/错误」「是/否」三种常见组合，其余按原样返回。

### 14.3 常用端口
